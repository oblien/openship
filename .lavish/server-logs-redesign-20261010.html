What this fixes

The current terminal has a large internal scrollback, but the initial history request is small and the panel does not reserve enough screen height.

Before this change · source reviewed by Astra

100 historical entries in a short viewer

The shared viewer fetched 100 entries, then attached a live stream. Its project context retained 1,000 entries and xterm held up to 10,000 rendered rows. The 460px minimum left little room to read; live appending also stopped when the retained array reached its cap.

Implemented behavior

1,000 entry backfill, responsive height, and explicit follow

The stream now backfills up to 1,000 entries in one connection. Sequence tracking keeps appending after the retained context buffer fills. Following, pausing and jumping to latest control the viewport; Stop stream still controls the connection.

Scope across OpenShip

Cover runtime logs in project, service, and Compose views

The shared TerminalLogs appears in Project → Logs → Terminal and each Service → Logs tab. Compose post-deploy runtime logs use LiveServiceLogsTerminal and now backfill 1,000 entries too. Shared deployment log panels receive the taller viewport and follow controls. Request logs remain a separate filtered list; interactive terminals keep their own controls.

New line behavior

Keep live output moving only while the user is at the tail.

When someone scrolls up, preserve their position and count new lines until they choose to return.

History size choices

Implemented default

Backfill 1,000 entries

The stream sends its supported tail request once and then continues live, avoiding a gap between a separate history fetch and the connection. Project copy and download retain the latest 1,000 entries; xterm scrollback is measured in rendered rows, not API entries.

Deferred

Defer a 5,000 entry option

First measure larger output performance and decide whether search, copy and download should share one retention limit. The API accepts much larger tails, but the UI should not request them without bounded client retention.

Recommendation and tradeoff

Keep the terminal readable and let it fill more of the screen.

The implementation raises history to 1,000 entries, preserves the current 14px terminal type, and uses a responsive 65vh viewport. It keeps project copy/download retention at 1,000 entries and xterm rendered-row scrollback at 10,000.

Behavior detail: searching or scrolling pauses follow and preserves the inspected position. Jump to latest is available immediately. Returning to the tail resumes follow unless the user explicitly paused it.

Keep these separate

“Stop stream” disconnects live output. “Following” only changes scroll behavior. A user can pause the view and keep receiving logs.
