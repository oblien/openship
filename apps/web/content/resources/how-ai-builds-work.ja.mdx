`openship deploy` を実行すると、アプリが公開される前に多くのことが起こります。 AI ビルド システムがどのように機能するかは次のとおりです。

## ステップ 1: フレームワークの検出

OpenShip はプロジェクトの信号をスキャンします:

- `package.json` 個のスクリプトと依存関係
- 設定ファイル (`next.config.js`、`nuxt.config.ts`、`Cargo.toml` など)
- Dockerファイルの存在
- ディレクトリ構造のパターン

これにより、信頼スコアによるフレームワーク一致が生成されます。 OpenShip が 95% の信頼度で Next.js を検出した場合、Next.js ビルド パイプラインが使用されます。 Docker ファイルがある場合は、それを直接使用します。

## ステップ 2: 構成の生成

検出されたフレームワークに基づいて、OpenShip は以下を生成します。

- **ビルド コマンド** - `npm run build`、`go build` など
- **コマンドの開始** - `npm start`、`./server` など
- **ポート マッピング** - アプリがリッスンするポートを検出します
- **環境変数** - フレームワークの規則に基づいて必要な変数を提案します

`openship.json` でこれらのいずれかをオーバーライドできます。

## ステップ 3: ビルドの最適化

AI レイヤーはビルドを最適化します。

- **レイヤー キャッシュ** - 依存関係レイヤーはソース コードとは別にキャッシュされます。
- **マルチステージ ビルド** - 運用イメージには開発依存関係が除外されます
- **並列ビルド** - マルチサービス プロジェクトを同時にビルドします

## ステップ 4: ヘルスチェック

導入後、OpenShip は以下を検証します。

- コンテナが正常に起動します
- ヘルスチェックエンドポイントが応答する
- SSL がプロビジョニングされ、有効である

いずれかのチェックが失敗した場合、デプロイメントは自動的にロールバックされます。
