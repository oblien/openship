OpenShip 0.9.1 では、アプリの選択、ランタイムの構成、保存されたセットアップへの戻り、次のリリースの準備など、デプロイに関する手順が改善されました。

## インストールする前に調べてください

[パブリック アプリ カタログ](/apps)] を使用すると、最初にダッシュボードを開かなくても、バックエンド、データベース、公開ツール、自動化を参照できます。カテゴリで検索またはフィルターし、アプリを開いてその機能、含まれるサービス、要件を確認します。

インストールは既存のセットアップ フローに従って続行されます。アプリとプランのリンクはサインインと検証を通じてリンク先を保持し、確認されたインストール設定はチェックアウト後に再開できます。

## より意図的なランタイム構成

生成された PHP ビルドは、ランタイム バージョン設定を通じて PHP 8.3 および 8.4 をサポートします。 Docker ソース ビルドでは、高度な運用イメージのオーバーライドも公開されています。レシピはアクティブ化前にランタイム機能と互換性をチェックし、保持されたイメージのロールバックは元のランタイム構成を保持します。

手動 Docker は、ローカル ビルドと固定されたロールバック アーティファクトを保持しながら、更新可能な変更可能なレジストリ タグを再デプロイします。差し替えイメージはサービス開始前に用意されます。準備が失敗すると、現在のコンテナが実行されたままになります。その後のマルチサービス カットオーバーは引き続き実行されます。

## すべてを再作成せずに回復する

保存されたクラウド サーバー リンクには、アカウントの不一致や一時的な障害に対する明確な再接続アクションとガイダンスが含まれています。既存の Web メール アプリケーションは、そのメール登録でプロジェクト リンクが失われた場合にも再接続でき、そのプロジェクトと永続ストレージを再利用できます。

移行では、選択されたパスのみをルーティングするドメインが保持されるようになりました。完全ルートとプレフィックス ルートはサービスに接続されたままとなり、一致しないリクエストは一致しないままになります。

## ワークフローと言語の改善

スタンドアロン アクション ワークフローでは、欠落している名前、ランナー、検証、またはアクセス設定に対する明確なガイダンスとともに、有効なカスタム YAML を保存できます。接続されたデスクトップと自己ホスト型インスタンスは、クラウド ワークフローとランナー操作を所有するクラウド インスタンスに転送します。

ロシア語がダッシュボード言語に加わり、Web メールはイベント ストリームを通じてライブ受信トレイの更新を受信します。

[完全な変更ログ](/changelog)を読むか、[機能ディレクトリ](/features)]を調べるか、インストールの[更新ガイド](/docs/guides/updating)に従ってください。
