<Callout title="Openship Cloud only">
Billing manages **Openship Cloud** resources for the selected managed server.
Self-hosted resources are free; linked installations can manage Cloud billing.
</Callout>

## Self-hosted has no billing

A plain **self-hosted** Openship has nothing to pay and shows no billing data —
the Billing area simply doesn't appear. You only pay for your own infrastructure.

## Openship Cloud

On Cloud, **Billing** is where you watch usage, change plan, and pull invoices.
Plans, prices, and per-plan limits are published on the
[pricing page](/pricing). Select the server to inspect its plan, metered
credits and usage. Shared Docker servers show actual host measurements
separately from provisioned capacity. A reserved disk size is not used storage;
credits are not minutes.
Cloud traffic is measured, but an unknown traffic ceiling is not displayed as
unlimited. Openship owns plan pricing and limits; each server's purchased
terms are kept for renewals.

| Tab | What it does |
| --- | --- |
| **Overview** | Current plan, billing period, and credit balance. |
| **Usage** | Metered usage over the period, charted. |
| **Plans** | Compare plans. New subscriptions open a hosted checkout; existing plan changes require support. |
| **Top-ups** | One-shot credits for an existing plan, without changing resource limits. |
| **Payment Method** | Opens the Stripe portal to manage cards. |
| **Invoices** | Opens the Stripe portal to download invoices. |

Cancelling from **Overview** flips the subscription to end at the close of the
period you've already paid for; new billable work is then blocked. You can resume
renewal before that period ends. Cancellation does not delete resources.

Choose a server from the right-hand card to view its own plan, renewal date,
usage and invoices. Existing servers keep their billing history when a plan ends.
Self-service upgrades and scheduled downgrades require Oblien's plan-change API;
Openship currently blocks full-price replacement of an existing subscription.
The return page verifies the specific checkout and credit delivery. It shows
pending, refunded, disputed or failed states instead of inferring success from
the browser URL. Invoices and payment methods open the selected server's
portal, isolated from other customers and the reseller account.

For the endpoints behind this screen, see the [billing API](/docs/api/billing).

## Make room for another deployment

For a **shared Docker server**, open the server to see live usage and its
projects. Container sizes are limits within that host. A new project does not
reserve another VM or disk. Source builds use available host capacity, and
image-only installs do not create a source builder. Stop an idle service if
memory is tight, or contact support to change the plan and choose **Apply plan capacity**
once the new entitlement is confirmed.
The resize preview lists every project that may restart and requires confirmation.
See [Servers](/docs/dashboard/servers) for progress, logs and recovery.

### Existing project-owned Cloud resources

Choose **Manage Cloud capacity** in Billing, or open it when a deployment needs
more available capacity. The pool shows reserved CPU, memory and storage.
A service-count allowance does not guarantee that another workspace will fit.

Source builds share this pool with running apps. Openship selects build CPU and
memory from Oblien's reported available capacity, within its workspace limits.
Existing runtime allocations stay reserved. Image-only installs need no source
builder. These rules also apply to catalog apps and their retries.

1. Choose **Adjust** beside a running project and edit its service CPU or memory.
2. Choose **Review changes**. Review the resulting workspace allocation and the
   services that may briefly restart.
3. Choose **Apply and restart**. The deployment uses the services' current images
   and saved settings, preserving persistent volumes. **Deployment logs** opens
   the normal deployment page.
4. Wait for capacity verification, then choose **Retry deployment**. The retry
   uses the original project rather than creating another installation.

Running Docker workspaces can be adjusted here. Other projects show why they are
unavailable; a resize also requires write permission on the project and its
services. Stopped workspaces still reserve capacity. Storage cannot be reduced
here, and workspace allocations include Docker overhead and build reservations.

After five minutes, automatic checks stop and **Refresh capacity** checks the
same operation again. Closing the dialog does not cancel a deployment. If an
adjustment fails, inspect its logs and refresh capacity before trying again.

For a source build, **Edit build resources** lets you set an optional CPU/memory
cap or choose **Automatic** again. This changes the next build, preserving
production settings. A smaller build may be slower or run out of memory.

## Credit warnings and recovery

When Cloud credits run low, a persistent dashboard banner links to the affected server's
billing page. The final warning level, grace credits, and exhaustion also show a dismissible
dialog. Credit-pack purchases appear only when top-ups are available.

See [credit warnings and recovery](/docs/guides/billing#credit-warnings-and-recovery) for
warning levels, notifications, and how the balance refreshes after a purchase.
