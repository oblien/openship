<Callout title="Self-hosted has no billing">
Billing applies to **Openship Cloud** resources. Self-hosted resources are free;
a linked installation can manage the connected Cloud organization’s billing.
</Callout>

## Self-hosted is free

If you run Openship on your own machine or server, there's **nothing to pay for the Openship software**. You only pay for your own infrastructure (the server, bandwidth,
and any third-party services you choose to run). Openship itself is open source
under the Apache 2.0 license — free forever, with no seat caps and no metering.

## Openship Cloud

Openship Cloud is the managed option: we run the servers, the edge, the backups.
Choose a paid plan to create Cloud projects, build and run workloads. Monthly
plans are $5 / $20 / $39 / $99, with custom Enterprise terms available through sales.
Choose **Custom** in Billing → Plans to configure CPU, RAM and disk yourself,
with a monthly price before checkout. Custom starts at $5 for 1 vCPU, 4 GB RAM
and 25 GB disk. Bundle discounts apply automatically; Enterprise remains
available for negotiated terms.
An account without a plan has no included Cloud compute. Hobby is a finite allowance for light use; continuous hosting can require top-ups.

The plans, their prices, and each plan's limits live in one place — see the
[pricing page](/pricing). The same catalog is served by
`GET /api/billing/plans`. Openship owns these prices, credit allowances and
limits. Your subscription's purchased terms are saved for renewals, even if the
catalog later changes. Credits are metered; capacity limits do not promise a
fixed number of runtime hours.

Each [managed Cloud server](/docs/guides/cloud-workspaces) has its own subscription.
In shared Docker placement, projects use the same host and disk. Project and
running-service allowances apply on that server. One service can use the
plan's full CPU/RAM ceiling, but the operating system, builds and other services
also need resources. Another project does not allocate another provider VM.

Current resource sizes, credit allowances and counts are published on the
[pricing page](/pricing) and shown before checkout. The server page separates
provisioned capacity from actual CPU, memory and disk usage, including a project
disk breakdown. Unavailable measurements are shown as unknown.

Build time uses the same credits as running apps, with no separate monthly minute
cap on these offers. Credits renew each billing cycle; they do not promise a
full month at maximum capacity. Existing subscriptions keep their purchased terms,
which are shown in Billing.

Shared-server source builds use available host capacity without reserving
another VM. Stopped servers and pending resource changes still count toward
provider allocation. Service counts do not promise every service can run at its
maximum size simultaneously.
Undeployed drafts do not use service slots.

Credit packs add 400 credits for $5, 1,700 for $20, or 4,500 for $50. A credit is not a minute: consumption depends on CPU, memory and transfer under the active Oblien rate card. Extra credits extend usage; upgrading the plan increases capacity. Previously purchased credit grants and prices remain attached to their saved subscription.

Every server plan includes **unlimited team members**. The subscription covers
that server and its allowances, without a per-seat charge.

## Managing your plan

The **Billing** area in the dashboard is organised as tabs:

| Tab | What it does |
| --- | --- |
| **Overview** | Current plan, billing period, and credit balance. |
| **Usage** | Metered usage over the period, charted. |
| **Plans** | Upgrade or downgrade — starts a Stripe Checkout session. |
| **Top-ups** | One-shot credits added to your existing plan; no increase to resource caps. |
| **Payment Method** | Opens the Stripe portal to manage cards. |
| **Invoices** | Opens the Stripe portal to download invoices. |

Cancelling keeps the plan active until the end of the period you've already paid
for, then blocks new billable work. You can undo a scheduled cancellation before
the paid period ends. Nothing is deleted by cancelling. Choose the managed server in
Billing to see its own portal, payment history and namespace allowance.

Top-ups remain available when an eligible paid plan runs out of credits, including
before a scheduled cancellation takes effect. They cannot restart an ended or
past-due plan; restore the subscription before buying more credits.

Contact support to change an existing server's plan. Self-service prorated
upgrades and next-cycle downgrades require provider support and are not available
yet; Openship blocks full-price replacement checkout for a live subscription.
When a changed entitlement is confirmed, Billing lets you review the new server
resources and affected projects before confirming a restart. Existing disks can
grow; shrinking requires moving data to a new server.
The checkout
return page waits for payment and credit delivery; pending fulfillment is not
shown as a successful purchase.

See the [billing API](/docs/api/billing) for the endpoints behind each of those
actions.

## Credit warnings and recovery

Cloud warnings use your workspace's current credit balance, including purchased credits.
The default warning levels are 80% and 95%. A compact notice in the bottom corner
can be opened or dismissed. It identifies the affected server without covering
the page. More severe warnings and a new billing period can show a new notice.

Choose **Buy more credits** to open credit packs when top-ups are available, or **Open billing**
to review your plan and options. After a purchase, wait for checkout to confirm that credits
were granted. The warning refreshes when you return to the dashboard and every minute while
it is visible. Buying credits does not increase a plan's CPU, memory, or other resource limits.

Billing alerts use your notification preferences. Email requires a verified address and a
working email connection; the dashboard warning remains available independently. Links in
alerts select the server subscription the alert belongs to. If you cannot access it, sign in with an
account with access to that server.
