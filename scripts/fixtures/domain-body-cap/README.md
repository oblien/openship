# Disposable per-domain body-cap proof

Two modes share the same request matrix and adapter transactions. Default mode uses a disposable OpenResty container and can test production Lua rate rules. `--native-nginx` uses `/opt/homebrew/bin/nginx` with the small, explicit compatibility shims below and leaves Lua rate behavior unproven.

Run from the repository root with Bun, Node 22 or newer, Docker Desktop, and OpenSSL. The repository dependencies must already be installed. Socket.IO is installed in a separate disposable directory; this fixture does not change a workspace package manifest or lockfile.

```sh
PROOF_ROOT="$(mktemp -d /tmp/openship-domain-cap.XXXXXX)"
mkdir -p "$PROOF_ROOT/socket-deps" "$PROOF_ROOT/docker-config"
printf '{}\n' > "$PROOF_ROOT/docker-config/config.json"
printf '{"private":true,"dependencies":{"socket.io":"4.8.1","socket.io-client":"4.8.1"}}\n' > "$PROOF_ROOT/socket-deps/package.json"
bun install --cwd "$PROOF_ROOT/socket-deps"
docker --config "$PROOF_ROOT/docker-config" pull openresty/openresty@sha256:2f09322c11964de09cbc53c9dbda84ed299a9f777a5824a67a46c85260bcda92
docker --config "$PROOF_ROOT/docker-config" pull node@sha256:06d7adf3e0ef61a13f1d28682726366f97a15aa1888c934d3ecec86c33918b53
bun scripts/fixtures/domain-body-cap-proof.ts --output "$PROOF_ROOT/proof" --socket-deps "$PROOF_ROOT/socket-deps"
```

To use the installed local nginx without Docker, run the first four setup lines and `bun install`, then:

```sh
bun scripts/fixtures/domain-body-cap-proof.ts --native-nginx --output "$PROOF_ROOT/native-proof" --socket-deps "$PROOF_ROOT/socket-deps"
```

Native mode launches only two owned foreground processes: nginx using the fixture's absolute config/PID/temp/log paths, and the Node counting origin on a free loopback port. It never invokes a system service manager. On exit it terminates those process handles, waits for exit, deletes local certificate private keys, and retains the config and logs. Every serving listener binds `127.0.0.1` on a dynamically allocated port.

The adapter's original files remain untouched in `sites-enabled` and phase snapshots. Native mode makes serving copies with exactly two compatibility operations: remove `access_by_lua_file` and `log_by_lua_file` lines (stock nginx has no Lua module), and remap `listen 80` / `listen 443 ssl` to free loopback ports. It asserts that every `client_max_body_size` directive remains byte-identical across that transformation. `native-shims.jsonl` records both hashes, and `configs/<phase>/native-serving/` retains the exact loaded copies. The small outer harness omits Lua shared dictionaries and the Lua management server in this mode. No body-size or proxy feature directive is invented by the shim.

Native success exits zero with `assertionStatus: PASS` and overall `status: PARTIAL`, because production Lua rate behavior was not executed. To close that gap once Docker is independently available, run the default OpenResty command above in a new empty output directory. Its `rate-limits.jsonl` must prove identical short/long-prefix results, `Retry-After`, and origin counts before and after the domain cap; source inspection alone does not close the gap. This fixture does not start or restart Docker.

The output directory must be new or empty. The fixture pins both container image digests and records their local image IDs. `--image` and `--node-image` accept explicit alternative images if needed. Anonymous Docker configuration avoids reading Docker account credentials. The Linux Node executable and its two supporting libraries are copied from the Node image into the fixture directory and removed on exit. Bun runs the adapter and HTTP matrix on the Mac; a Node helper runs the Socket.IO clients, and the container runs OpenResty plus the Node counting origin. No production installation, service, account, or hostname configuration is touched. The Socket.IO helper's private agent resolves only the two fixture hostnames to loopback, preserving their real Host/SNI without changing machine DNS or `/etc/hosts`.

Only dynamically allocated **127.0.0.1 host ports** are published: HTTP, HTTPS, and the private fixture management endpoint. OpenResty listens on container-internal ports 80/443/9145 so Docker can forward those loopback bindings. The origin binds **127.0.0.1:3000 inside the same disposable container** and is never published. Docker port allocation fails closed if a free-port probe races another process. The unique container and all its processes are removed on normal exit, failure, SIGINT, or SIGTERM. SIGKILL cannot run cleanup; the exact owned name is present in `commands.log` if manual removal is necessary. Never remove other containers.

## Production code exercised

The fixture imports the shared `resolveDomainProxySettings` and the exported `NginxProvider` directly from source. Every vhost comes from `NginxProvider.registerRoute(RouteConfig)`, including both HTTP and HTTPS server blocks, ordinary proxy locations, forwarding headers, body-size directives, and production Lua guard/logger references. **In OpenResty mode no serving directive is rewritten.** The stored-route replay setup removes only generation comments, as described below. Native mode uses only the compatibility operations listed above. The fixture does not hand-write `client_max_body_size` at server or location scope. It asserts exactly one generated cap per serving server when set, and zero when inheriting the installed HTTP default.

The small outer nginx harness supplies a worker, logs, fixture paths, the real `EDGE_CLIENT_MAX_BODY_SIZE` default, and a sites include. In OpenResty mode it also supplies real `EDGE_SHARED_DICTS` and a management location running production `mgmt_api.lua`; production Lua files are mounted read-only at their expected path. One worker avoids an unrelated load benchmark; this is functional evidence. Geo databases and password protection are outside this fixture.

The executor uses real `LocalExecutor` file operations in the disposable output directory. Its exact command allowlist accepts `buildReloadCommand(paths)` and the adapter's two literal inventory operations: listing its container sites directory and `grep -L` for the current generation marker. Config tests and reloads execute against the real proxy. The inventory commands execute in the owned container, whose standard sites path is a second bind mount of this fixture's sites directory. Native mode maps only those two read-only inventory operations to the owned local directory. Every unexpected adapter command is refused. This is a fixture transport shim, not a simulated config validator or a simulated reload. The production `containerEdge` transaction and rollback code runs in both modes. No Linux bare-host PID ownership or system service probing is claimed.

For TLS, OpenSSL makes one-day self-signed certificates for `api.fixture.test` and `events.fixture.test`. HTTPS requests use the hostname for SNI and Host, with verification disabled only for these local certificates. Private keys are deleted on exit; public certificates and configs remain as evidence. Reproduce the proof by rerunning the script, which generates fresh keys.

When a real cert exists, the production HTTP location normally redirects to HTTPS. Body tests on the actual HTTP listener include `X-Forwarded-Proto: https` to exercise the renderer's existing serving branch for a TLS-terminating front proxy. They still send plaintext HTTP bodies to the HTTP listener. HTTPS requests terminate TLS at OpenResty. This fixture does not claim the ordinary redirect branch accepts an upload body.

## Assertions and retained evidence

- Project-only `2m` baseline on both hosts, then an inherited `2m` API domain and custom `1m` events domain. HTTP and HTTPS each get cap−1, cap, cap+1 and 1.5 MiB for **Content-Length and actual chunked transfer**. Accepted requests return the origin's measured byte count. Rejected requests must produce Edge 413 with **zero origin request-start events**, not merely zero completed uploads.
- A project change to `3m` permits 2.5 MiB on the inheriting host while the custom `1m` host still rejects 1.5 MiB. Clearing the domain override restores the complete `2m` boundary matrix. Both caps unset render no vhost directive and inherit the installed `50m` default; a 1.5 MiB smoke request verifies that case (the fixture does not send a full 50 MiB boundary matrix).
- A real Socket.IO 4.8.1 server and client establish polling connections and exchange acknowledged application messages. A 1.5 MiB polling event succeeds under `2m`, and under `1m` its POST never reaches the origin. Server `maxHttpBufferSize` is separately set to 2 MiB.
- Polling connections upgrade to a real WebSocket on both hostnames and protocols. A 1.5 MiB message succeeds even on the `1m` domain after upgrade. A message larger than the application's 2 MiB limit disconnects and produces no application message event. `socket.io.jsonl`, origin upgrade events, and access-log 101 responses retain the protocol evidence.
- **OpenResty mode only:** the actual Lua `/rules` management handler installs identical rate rules before and after domain caps. For each hostname/protocol, the shorter prefix gives `[200,429]`, and the longer matching prefix `[200,200,200,429]`. 429 carries `Retry-After: 1`, rejected requests never reach the origin, and the vhost stays byte-identical during reload-free rule updates. Rules and zones are production code; no Lua limiter is stubbed. Native mode reports this gap and does not substitute a fake limiter.
- Actual `NginxProvider.activateCert` runs once for each existing domain with its ephemeral certificate already present. Each call must produce one real validated reload and preserve the full generated config, sidecar, and independent `2m`/`1m` caps in both HTTP and HTTPS server blocks. After **each** activation, both hostnames receive 1.5 MiB requests over HTTP/HTTPS with Content-Length and chunked transfer; the `2m` domain must reach the origin and the `1m` domain must return Edge 413 without an origin request.
- A **fresh provider instance** runs actual `reapplyStoredRoutes`. Its setup removes only generation comments from both fixture vhosts, preserving all serving directives and saved RouteConfigs. Real container `ls`/`grep` inventory must find both stale routes; the method must report both repaired with no failures, perform two real validated reloads, and restore byte-identical generated configs and sidecars. The same eight 1.5 MiB request/counter checks run afterward. `replay-results.json` retains all three operations, before/after hashes, per-server caps, reload counts, repair results and 24 request rows. This exercises the stored-route replay routine while the container, proxy master and origin stay running; it is **not** a whole-OS restart, container restart, ACME issuance or ACME renewal.
- An injected invalid directive causes **real `nginx -t` failure** during adapter registration. The production transaction restores the exact previous vhost and route sidecar. An invalid signal argument causes **real reload-command failure after a successful config test**; the same rollback runs. Both retain matching before/after SHA-256 values and prove the prior `2m` behavior still serves over HTTP and HTTPS. The invalid directive is deliberate fault injection, captured in `rollback-invalid-candidate.conf`. The signal failure models failure before delivery of HUP; it does not prove recovery from a kernel accepting HUP followed by an asynchronous master failure.

Artifacts include `summary.json`, `stdout.log`, exact external commands and captured output in `commands.log`, every config test in `config-tests.log`, phase-by-phase generated `.conf` and `.route.json` files, raw origin events and `origin-counters.json`, JSON/CSV status and byte matrices, Socket.IO results, rate results when executed, rollback results, access/error logs, and relevant source snapshots/hashes. A zero exit and `summary.json` status `PASS` mean only these local assertions passed in OpenResty. Native success reports `PARTIAL` as explained above. Failed runs retain diagnostics and still clean up their owned processes and keys.

The source inventory includes the renderer, shared resolver and proxy settings, OpenResty harness constants, every production Lua module, and the fixture executables. A completed OpenResty `PASS` with rate evidence supersedes a prior native-only `PARTIAL`; preserve the earlier run and failures as historical evidence rather than changing their recorded results.

## Negative control

Run the same command (including `--native-nginx` if needed) with a fresh output directory and `--negative-control-project-only`. This intentionally feeds only project settings to the real renderer, reproducing the old per-project behavior while keeping the same expected domain-specific HTTP matrix. The baseline passes, then an events-domain body just over `1m` reaches the origin with 200 where the fixture expects Edge 413. The process must exit nonzero. This is an explicit old-behavior control, not a claim that the feature source was edited or an unmodified historical checkout was executed.

## Limits

This proves local edge behavior, the renderer's actual config transaction, actual certificate activation on existing fixture domains, and actual stored-route replay through a fresh provider instance. It does **not** prove domain API authorization/persistence, migrations, desired-versus-applied UI state, import/export, later deployment, ACME issuance/renewal, whole-OS or container restart, distributed locks, Linux bare-host service ownership, king-dev, or production operation. Those need separate parent-owned tests. The shared source is under active implementation; `source-snapshot/`, source hashes, and the base Git head identify what was read for the run, rather than pretending the base head contains all uncommitted feature changes.
