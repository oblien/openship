# SDK migration preservation audit

Checkpoint: September 14, 2026. The migration mostly relocates the existing API backend into `packages/platform/src/engine`. Shared operations and native lifecycle code are new, and some retained services have deliberate changes. The public SDK calls those operations; it does not reconstruct HTTP requests or invoke controllers in native mode.

The [SDK plan](ship-sdk-plan.md) remains in progress. Preserving the existing backend and exposing every platform feature through a public native operation are separate checks. Moving a service into the engine does not, by itself, make it a supported SDK method.

## Reproduce the comparison

From the repository root:

```sh
node --test scripts/sdk-relocation-compare.test.mjs
node scripts/audit-sdk-relocation.mjs \
  --baseline-report=docs/ship-sdk-preservation-checkpoint.json \
  --json=/tmp/openship-sdk-relocation.json
```

The [audit script](../scripts/audit-sdk-relocation.mjs) can use the recorded Git blobs and API file inventory, so staging deletions or committing the moves does not silently change the baseline. It verifies the original SHA-256 and Git object hash before comparison. Committed originals require the original Git history; the single staged-only original is embedded as exact base64 bytes in the checkpoint so it survives Git garbage collection. A missing or inconsistent original fails the audit instead of falling back to a different version.

Files introduced by a later upstream merge use a full immutable `baselineCommit` in the relocation manifest. The audit reads those originals from that commit and includes its API file inventory. Existing checkpoint baselines remain unchanged. The command above therefore reports the current expanded migration while retaining the earlier evidence.

Without `--baseline-report`, the default still reads staged pre-move sources where available and falls back to `HEAD`; `--baseline=<git-ref>` explicitly selects a revision. These options can produce different results after staging or changing revisions. The recorded checkpoint was generated using a temporary copy of the saved pre-move index, with `HEAD` at `541ba903fdcd8959054b1fb8805749632a1dafe9`. The script never edits application source or the Git index.

Raw equality compares buffers. The module-path-only comparison masks only the contents of syntactic import/export/require string literals and TypeScript import-type literals, preserving every surrounding character. Computed module expressions are not exempted. The separate normalized comparison parses TypeScript and compares emitted JavaScript tokens; ordinary string values are not treated as paths. Static imports are compared separately, preserving declaration order, and the JSON includes their before/after forms. Missing targets, missing expected baselines, unaccounted API deletions, duplicate mappings, and forbidden engine imports cause a failing exit status. Changed implementations remain listed for review; a passing accounting audit does not certify them as behaviorally equivalent.

Token equality is useful evidence that implementation was retained. It does not prove identical behavior when dependencies, configuration, runtime, or calling context change. Computed module loading and the behavior of external providers require separate review and tests.

The 13 literal-comparison tests pass, including deliberately omitted authorization branches, changed ordinary strings, import bindings/order, types, comments, formatting, computed imports, invalid syntax, and invalid UTF-8. Repeating the audit from the recorded baseline reproduces every comparison and hash after the staged deletions. Negative checks confirm altered baseline evidence and an invented unmapped missing API path cause a failing audit without deleting application files.

## Scope header and HTTP result adapter review — September 13

The analytics and issues controllers use [operationData](../apps/api/src/lib/operation-context.ts) to await a shared operation, apply its returned authorized context to the HTTP request, and unwrap the data for the existing response envelope and status. The helper contains no analytics, issue aggregation, persistence or provider logic. Native SDK calls bind the same kernel operations, including validation, authorization, retained services and response projection. Routes declaring operation-managed auditing rely on those operations to emit their required audit events; the helper coordinates the HTTP middleware rather than writing another event.

`X-Openship-Scope: fixed` is a client-requested scope constraint. It does not authenticate the caller or grant access. The centralized authentication adapter now rejects unsupported header values and requires an explicit, nonblank `X-Organization-Id` for fixed scope, returning `400 VALIDATION_ERROR`. Previously, invalid values silently selected resource-derived scope, and missing organizations could fall back to the session default. Omitting the scope header preserves the existing HTTP behavior. Native contexts do not use this HTTP header.

Seven new middleware regression cases failed against the permissive parser and passed after the correction. The focused run passed 146 API middleware/analytics/issues tests and 20 SDK HTTP/client tests; API TypeScript also passed. The existing real-router/native analytics and issues parity tests cover restricted rows and counts, foreign-resource denial, audit attribution without duplicate events, range validation and stream lifecycle. These are focused checks, not a replacement for the earlier full-suite checkpoint or the remaining live-Cloud release checks. Existing staged changes were preserved; this review did not update the Git index.
